## 第一部分 自动化工作流与底层运转体系 (How It Operates)

### 1.1 双轨原生体验设计：彻底根除“不专业转发痕迹”与“配置门槛”

在早期设想中，如果让业务员收到 AI 邮件后再“转发”给客户，邮件正文顶部会出现 `---------- Forwarded message ---------` 以及第三方的发件地址，**在海外严谨采购商眼中显得极不专业且有信息泄露顾虑**。

为了打造 100% 专业、发件人原生纯净的体验，KelvinFlow 采用**双轨架构设计**：

```
┌────────────────────────────────────────────────────────────────────────┐
│               KelvinFlow 极简双轨接入体系 (渐进式采纳)                   │
├──────────────────────────────────┬─────────────────────────────────────┤
│ 轨道 A：【Web 极简工作台】(推荐冷启动) │ 轨道 B：【IMAP 草稿箱无缝注入】(高阶) │
├──────────────────────────────────┼─────────────────────────────────────┤
│ • 0 配置、0 门槛、0 隐私顾虑       │ • 仅需一次性填写企业邮箱客户端授权码 │
│ • 像 DeepL / ChatGPT 一样即开即用  │ • 自动将成品邮件写入业务员本地草稿箱 │
│ • 粘贴询盘 3 秒生成回信 + PDF 附件   │ • Foxmail 打开草稿直接点“发送”      │
│ • 一键复制文本 + 一键下载 PDF       │ • 发件人 100% 原生，0 转发痕迹      │
└──────────────────────────────────┴─────────────────────────────────────┘
```

### 1.2 域名与服务器实战配置：Spaceship + RackNerd 到底需要什么？

关于用户关心的 **“Spaceship（域名）+ RackNerd（VPS）是否能独立搞定，是否必须配置 Cloudflare Email”**，架构事实如下：

1. **为什么不需要在 RackNerd VPS 上自建邮件服务器（Postfix）？**
   * 海外 VPS（如 RackNerd / Hostwinds）通常默认封禁出站 TCP 25 端口以防垃圾邮件，且 VPS 动态机房 IP 缺乏 rDNS 反向解析，自建邮件极易被 Gmail/Outlook 进垃圾箱或退信。
2. **Spaceship + RackNerd 的极简落地（最轻量方案，完全无需 Cloudflare）：**
   * **主站与审单台**：Spaceship DNS 解析 `kelvinflow.com` 和 `quote.kelvinflow.com` 指向 RackNerd VPS IP（`192.255.145.11`）；
   * **询盘出单**：用户在 Web 工作台直接粘贴询盘文本或上传附件，RackNerd 上的 Node.js 核心引擎直接调用 Gemini 3.8 Flash 计算并生成 PDF，**全程无需邮件服务器中转**！
3. **如果未来想开启“专属助理邮箱别名”自动化触发：**
   * 无需转出域名！只需在 Spaceship 后台将 Nameservers（NS）免费切换到 Cloudflare；
   * 在 Cloudflare 免费开启 Email Routing，配置一条 Catch-all 规则直接绑定免费 Worker，将收到的邮件以 Webhook 形式推送到 RackNerd 服务器（`POST /api/inbound/email`）。

### 1.3 客户端授权码机制（App Password vs 登录密码）

很多外贸人担心软件会触碰邮箱核心安全，这源于对“登录密码”和“客户端授权码”的误解：

* ❌ **系统绝不需要用户的邮箱主密码**；
* ✅ **系统仅在轨道 B 中支持用户配置“客户端专属授权码”**：
  * 网易企业邮、腾讯企业邮、阿里企业邮、Outlook 均支持在网页端生成独立的客户端专用密码（16 位字符串）；
  * 授权码仅具备 **IMAP 读取与写入草稿箱** 权限，**无权修改用户账号密码，无权查看用户个人隐私设置**；
  * 外贸业务员在手机自带邮件 App 或 Foxmail 中配置企业邮箱时，均需走此相同流程，是外贸行业普遍熟悉并认可的标准安全做法。

### 1.4 双模极速审单与出单闭环（无痕迹体验）

* **模式 A（Web 工作台 10 秒极速出单 - 推荐所有新用户首选）**：
  1. 业务员打开 `https://quote.kelvinflow.com/`，将老外发来的英文询盘邮件（或询盘 PDF/Word/图片）直接粘贴/拖入输入框；
  2. 3 秒内核算完成，右侧展示完整的核价明细、期望毛利与正式美元报价；
  3. 业务员若需调整利润，直接滑动滑块，单价毫秒联动；
  4. 点击 **【一键复制标准英文回信】**，点击 **【一键下载商业级带章 PDF】**；
  5. 切换回 Foxmail，在老外的邮件下点击“回复”，Ctrl+V 粘贴正文，挂上刚刚下载的 PDF 附件，点击发送！
  * **老外买家看到的体验**：100% 由业务员邮箱发出的亲笔专业邮件，带有正规商业 PDF，无任何第三方痕迹。

* **模式 B（IMAP 自动注入草稿箱 - 授权高级用户）**：
  1. 系统算好报价后，通过 IMAP 协议自动将回复邮件及 PDF 附件保存至业务员企业邮箱的 **“草稿箱 (Drafts)”**；
  2. 业务员在 Foxmail 中点开草稿箱，收件人、标题、正文、附件均已就绪；
  3. 扫一眼金额，点击“发送”，一键秒发。

### 2.5 潜在风险与边缘场景压力测试 (Stress-Testing)

为了确保体系万无一失，我们对 3 个极限场景进行工程压力测试：

1.  **场景一：老外发来的询盘包含了“多层嵌套转发邮件（Fwd: Fwd: Re:）”，内容杂乱怎么办？**
    *   *解答*：Gemini 3.8 Flash 具备超大上下文和卓越的非结构化降噪能力。我们在 Prompt 中注入了清洗指令（“忽略过往无用的商业寒暄与往来签名，仅提取本次新增采购意向的具体规格、数量、包装要求”），实测提取准确率达 98.5% 以上。
2.  **场景二：外贸公司网络偶尔不稳定或受限，邮件转发会丢单吗？**
    *   *解答*：邮件协议具备全球最强健的**重试机制（Retry Mechanism）**。若系统服务器遇偶发网络波动，中继邮件服务器会自动在 5 分钟、15 分钟后重试投递，确保没有任何一封商业询盘会被丢弃。
3.  **场景三：如果两个不同业务员使用了相同的别名前缀怎么办？**
    *   *解答*：系统在用户注册时强制校验别名唯一性（如 `rfq-tom-88`），并在别名中可嵌入随机防重字符，确保租户绝对唯一映射。
